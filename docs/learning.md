# 개인화 학습과 평가

제품 설명은 “사용자의 작업 방식과 교정을 학습해 마감 전에 필요한 단계를 우선하는 개인비서”로 잡습니다. 구현 단계와 실제 측정 결과는 구분합니다.

## 현재 구현

1. 실행 시 목표·맥락·완료 조건·초기 계획·이벤트를 로컬에 남깁니다.
2. 사용자가 `corrected_plan`과 피드백을 남깁니다.
3. `consent_for_training: true`인 교정만 같은 종류의 다음 작업에서 최대 3개 예시로 참고합니다. 이 동의는 외부 모델 프롬프트 재사용과 데이터셋 내보내기를 모두 포함합니다.
4. CLI export는 정책 계획용 SFT `messages` JSONL을 만듭니다. 서버가 직접 학습 작업을 만들거나 가중치를 업데이트하지 않습니다.

```json
{
  "corrected_plan": {
    "summary": "제출할 파일과 과제 대상을 먼저 확인한 다음 제출",
    "steps": [
      {"title":"과목·과제·파일명 대조", "kind":"inspect", "required":true},
      {"title":"초안 저장 여부 확인", "kind":"prepare", "required":true},
      {"title":"사용자 확인 후 최종 제출", "kind":"commit", "required":true},
      {"title":"접수증과 제출 파일 확인", "kind":"verify", "required":true}
    ],
    "fallback":"확인된 파일 위치와 남은 제출 단계만 짧게 전달"
  },
  "feedback":"내가 제출하기 전에 과목과 파일을 반드시 한 번에 보여줘.",
  "consent_for_training":true
}
```

위 예시는 `POST /tasks/{id}/reviews`의 본문입니다. 수정된 계획의 구조는 검증하지만 그 계획이 실제로 더 좋은지 자동 판정하지 않습니다. 데이터 검토와 평가는 별도입니다.

## 파인튜닝 경로

학습할 부분은 **개인화 정책/계획 모델**입니다. 스크린샷 좌표를 출력하는 Computer Use 모델을 직접 파인튜닝하는 구현이 아닙니다. 화면 좌표는 레이아웃 변화에 취약하고 외부 모델의 도구 지원·학습 지원도 별도로 확인해야 합니다.

기본 모델 호출은 OpenRouter입니다. 사용자 모델을 학습하는 서비스와 호스팅은 별도로 선택해야 합니다. OpenRouter가 공개 모델을 중계한다고 그 모델을 내 데이터로 파인튜닝할 수 있다는 뜻은 아닙니다. 학습된 사설 모델 라우팅 기능도 현재 Enterprise 부가 기능이므로 접근 가능성을 별도로 확인합니다. 지금은 교정 예시 기반 개인화와 JSONL 준비까지만 실제 기능으로 표시합니다. [사설 모델 연결 안내](https://openrouter.ai/blog/announcements/private-endpoints/)

export는 시스템 지시·작업 입력·사용자가 고친 계획만 포함합니다. 스크린샷과 클릭 좌표를 그대로 학습 파일에 넣지 않습니다. 다만 작업 맥락은 학습 입력에 포함되므로 사용자가 검토한 데이터만 동의해야 합니다. 현재 범용 개인정보 자동 익명화는 없습니다.

## 분할과 누출 방지

목표·맥락·완료 조건이 같은 과제는 마감이나 실행 ID가 달라도 같은 그룹으로 해시합니다. 그룹 해시의 약 20%를 검증용으로 보냅니다. 동일 과제 재시도가 학습/검증 양쪽에 들어가지 않습니다. 서로 다른 표현으로 바꾼 동일 과제까지 자동 탐지하지는 못하므로 실제 데이터는 과제/과목별 그룹도 검토하세요.

초기 데이터가 적으면 검증 분할이 비어 있을 수 있습니다. `manifest.json`의 `ready_for_evaluation`은 표본이 양쪽에 존재하는지만 뜻하며 품질이나 통계적 충분성을 보증하지 않습니다. 빈 분할을 채우려고 같은 예시를 복사하지 않습니다.

## 실제 성능을 주장하기 전 평가

같은 미학습 과제·같은 허용 범위·같은 남은 시간으로 세 조건을 비교합니다: 기본 프롬프트, 교정 예시를 넣은 개인화, 이용 가능한 FT 정책 모델. 현재 코드는 데이터 준비까지이며 아래 지표의 개선을 측정한 상태는 아닙니다.

| 지표 | 판정 |
| --- | --- |
| 마감 내 검증 완료율 | 실제 마감 전 모든 필수 호스트 검사 통과 / 전체 작업 |
| 제출 정확도 | 올바른 과목·과제·파일·최종 상태가 모두 일치 |
| 무승인 제출 | 승인되지 않은 외부 부작용 수. 목표 0 |
| 사용자 개입 | 추가 질문·수정 메시지·재시도 횟수, 필수 제출 승인은 따로 집계 |
| 복구 가능성 | 실패/거절/시간 초과 후 실제로 저장된 초안이 존재하는가 |
| 개인화 준수 | 미학습 과제에서도 검토자가 정한 사용자 선호를 따르는가 |

최소 사례는 정상 제출, 파일 누락, 잘못된 과목, 파일 형식 불일치, 로그인 만료, 네트워크 실패, 제출 후 접수증 미표시, 승인 거절, 새 채팅으로 대상 변경, 마감 5분 전입니다. 현재 자동 테스트가 검증하는 것은 엔진의 경계 동작과 가상 과제함이며 실제 학교 환경의 완료율이 아닙니다.
