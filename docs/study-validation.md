## 자동으로 검증한 동작

- 보정 전 좌표 차단, 9점 학습과 별도 5점 검증, 점별 안정화 후 12개 유효 샘플, 유효율 80%와 해상도 비례 120/220 DIP px 게이트.
- 상수 특징·틀린 검증 정답·비유한 입력 거절. 유효한 화면 밖 좌표는 잘라 붙이지 않고 유지.
- 8초 시각 알림, 20초 잔소리, 2초 복귀, 90초 반복 제한. 눈 감김·결측·프레임 공백·미검증·자세 품질 저하 때 누적 증거 초기화.
- 필기·오버레이·도움·휴식·생각 유예·알림 끄기에서 잔소리 억제.
- 질문 직전의 신선한 안정 응시만 고정. 뒤의 오버레이 응시가 기존 질문 대상을 덮어쓰지 않음.
- Retina 2×·음수 모니터 원점·경계 크롭 변환. 실제 캡처 직전 자체 창을 숨기고 `showInactive`로 복원하는 호출 순서.
- 키 반복 무시, 캡처 준비 전에 키를 놓으면 폐기, 키 해제 전 전송 차단, 20초 watchdog 후 늦은 해제로도 전송 불가, 권한 철회 폐기.
- 응시 대상이 없으면 원래 캡처를 사용해 수동 선택 요청. 취소 후 캡처와 녹음 참조·대기 타이머 정리.
- 잘못된 미디어·무음·동의 없음·전사 실패 때 설명 호출 없음. 녹음/캡처/이미지 프롬프트 비저장, 화면 답변 학습 내보내기 제외.

## 재실행

```sh
# 프로젝트 폴더에서 (이전 Computer Use SDK 시험은 선택 의존성 설치 필요)
python3 -m unittest discover -s tests -q
cd overlay
npm run check
npm test
```

브라우저 통합 시험은 `LAST_HOUR_BROWSER_TESTS=1`이며 Chrome/Playwright가 필요합니다. 외부 모델 호출은 일반 회귀 테스트가 모의 처리하므로 테스트 실행만으로 과금되지 않습니다. 위 실호출은 별도로 한 번 수행했습니다.

별도 UI 시험: `python3 tests/browser_ui_qa.py` (Playwright와 macOS 시스템 Chrome 필요). `tests/fixtures/voice-question.wav`는 OS TTS로 만든 한국어 시험 발화이며 사용자 마이크 녹음이 아닙니다. UI 시험은 실제 WebM/Opus를 만들지만 네이티브 전송과 모델 요청은 모의 처리합니다.

## 2026-11-08 · 실제 보정 실패 보고에 따른 수정

사용자가 9점 수집 후 ‘눈의 위치 변화가 부족해요’라는 오류가 반복된다고 보고했습니다. 이전의 큰 합성 특징으로 만든 테스트는 실제 랜드마크 추출 결함을 발견하지 못했습니다. 사람의 정확도는 여전히 미통과입니다.

수정: 수직 홍채 위치의 기준을 함께 움직이는 눈꺼풀 중심에서 눈꼬리 선으로 변경했습니다. 눈 특징의 고정 최소 분산 조건을 제거하고 개인 신호 크기에 맞춰 정규화하며, 머리 특징은 별도의 보수적인 스케일을 적용합니다. 판정은 동일한 별도 5점 오차·유효율 기준을 유지합니다. 멈춘 영상 프레임은 유효 샘플로 중복 수집하지 않습니다. 카메라는 1280×720을 우선 요청하며 장치가 지원하는 값으로 협상합니다.

회귀 시험에는 눈꺼풀과 홍채가 함께 움직이는 실제 추출 경로, 기존 거부 기준보다 작은 신호, 독립적인 랜드마크 잡음, 머리 기울기, 틀린 검증 정답, 영상 프레임 중복, 메뉴 막대·Dock 여백을 추가했습니다. Node 28개 통과입니다. 이는 사람의 시선 정확도 증거가 아닙니다.

실제 Mac에서 하단이 화면 밖으로 잘리는 문제도 발견해 보정·점 표시 창을 workArea에 열도록 수정했습니다. 보정 목표는 실제 content bounds에서 전체 모니터 DIP로 변환하고 캡처는 전체 모니터 기준을 유지합니다.

음성 권한 확인은 손쉬운 사용 미허용으로 차단됨을 확인했습니다. 보안 설정은 변경하지 않았습니다. 실제 단축키·마이크·시선 오차 재검증은 대기 중입니다.

화면 이벤트 수정: 선택한 모니터의 bounds/scaleFactor/rotation 변경에만 보정을 해제합니다. Dock·메뉴 막대의 workArea 변경이나 다른 모니터의 변경으로 카메라를 끄던 문제를 수정했고, 사용 중인 카메라가 유지되는 장치 목록 갱신도 무시합니다. Node 총 29개 통과입니다.

## v0.5 UniGaze 교체 검증

사용자 요청으로 UniGaze-L 사전학습 모델을 로컬 Metal GPU에 통합했습니다. 공식 가중치 해시/구조 확인, L/B·FP32/FP16 실측, 공개 예제의 MediaPipe→정규화→신경망 추론, 실제 Electron 모델 로딩을 확인했습니다. [상세](neural-gaze.md). 새 모델의 사용자 시선 정확도는 아직 재검증하지 않았습니다.

Python 기본 회귀 63개 중 선택 ML 환경의 2개는 skip이며, `.gaze-venv/bin/python -m unittest tests.test_neural_gaze -q`로 관련 3개가 모두 통과했습니다. Node 33개, UI 9개 흐름 통과입니다. 얼굴 영상·원시 시선은 이 시험으로 저장하거나 외부 전송하지 않았습니다. 공개 예제 이미지는 중간 시험 fixture로만 사용했습니다.


## 2026-11-08 · 텍스트 화면 질문과 보정 저장

- 실제 OpenRouter: 인증된 로컬 `screen-help` HTTP API에 직접 작성한 확률 이미지와 텍스트 질문을 보내 응답 수신. 약 6.01초. STT는 호출하지 않는다. 답변은 화면에 있는 빨간 카드 4장·별 카드 2장으로 설명했고, 화면에 없는 총 10장 정보는 추측하지 않았다. 이미지가 저장 JSON에 남지 않음을 확인했다. `qa/live-screen-result.json` 참조.
- UI: 화면 질문 버튼·선택 전 전송 없음·선택 후 답변 표시·선택 취소 시 전송 없음 확인. 기존 음성 테스트를 포함해 모의 native bridge Chrome 11개 흐름 통과, JS 오류 0.
- 보정: 검증된 계수만 저장·저장소 재생성 후 동일 계수 복원·미검증 복원은 좌표 없음·새로운 5점 검증 통과 후 활성화·환경 불일치/손상/재검증 실패 차단·최대 8개·삭제를 Node에서 검증했다. 실제 사용자의 새 UniGaze 보정 정확도 측정은 남아 있다. 기존 메모리 전용 버전에서 이미 소실된 보정은 소급 복원할 수 없다.
- 전체 Python 65개(선택 ML 환경 2개 제외), Node 41개 통과.
- 실제 macOS 앱에서 화면 질문 UI와 예제 학습 시작까지 확인했다. 이후 컴퓨터 제어 도구가 반복 지연·타임아웃을 반환해 네이티브 캡처→답변의 실기기 완료는 검증하지 못했다. 화면 녹화 권한 또는 전역 키 권한을 임의 변경하지 않았다.
