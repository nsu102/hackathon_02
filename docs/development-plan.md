# Study Signal v0.6 구현과 확인 상태

현재 요청의 구현은 음성 중심 UI, 정밀 좌표와 독립적인 화면 방향 감지, macOS 메뉴 막대 설정으로 정리했다. 예전 ‘보정 통과＋학습 영역 필수’ 기본 조건을 대체한다.

| 항목 | 구현 | 확인 |
|---|---|---|
| 음성 UI | 입력창·세 프리셋 제거, 말하기/보내기 버튼, OS 음성 읽기 | Chrome 모의 native bridge에서 실제 WebM 녹음·답변·취소 |
| 질문 맥락 | 시작 시점 화면 고정, 선택 모니터 전체 또는 수동 문단 | Retina/음수 좌표·명시적 전송·기한 폐기 단위 시험 |
| LLM | OpenRouter STT→기존 Vision 모델, 무음/실패 차단 | 합성 한국어+작성 이미지 실호출 6.96초 |
| 집중 신호 | 정면 기준 약 2초, 신경망 방향·머리 방향, 6상태, 원인 표시 | 합성 방향으로 8/20/2/90초 통합 시험 |
| 정밀 시선 | 실험 설정으로 이동, 저장·5점 재검증 유지 | 저장 복원·실패 차단 단위 시험 |
| 메뉴 막대 | SVG+Retina 아이콘, 설정/감지/알림/음소거/휴식/종료 | 템플릿 이미지·메뉴 콜백 단위 시험, Mac 앱 기동·실제 Tray 위치/1×·2× 등록 |
| 사용자 설정 | 감도·말투·읽기·불투명도·모니터 저장 | UI 모의 시험 |

Node 50개, Python 66개 중 선택 ML 환경 2개 제외, UI 13개 흐름 통과. 실제 Mac의 v0.6 UI·설정·모델 기동을 확인했다. 컴퓨터 제어 도구가 OS 메뉴 막대 접근에서 타임아웃을 반환해 메뉴 클릭 전 과정을 장비 통과로 표시하지 않는다. 단, 표시 완료 뒤 실제 Tray 위치와 템플릿·Retina 로딩은 네이티브 API로 확인했다.

남은 검증은 사람의 응시·이탈 정확도/정상 학습 오탐률과 실제 마이크/캡처/권한·전역 단축키 종합 시험이다. 코드 시험 통과를 사람의 집중 판정 정확도로 간주하지 않는다. 앱은 관측 상태와 측정 불가 이유를 표시한다. [검증 기록](study-validation.md)

후속 사용자 시험: “응시·이탈 상태가 바뀜” 보고를 받았다. 사람의 방향 상태 전환 기능은 사용자 확인을 받았으며, 정량 정확도/오탐률과 실제 알림 시각 측정은 남아 있다.
